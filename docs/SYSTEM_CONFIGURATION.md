# 系统设置与配置归属

系统页只管理跨能力共享、且确实由当前运行架构读取的本机设置。数据库中出现一个键，不代表它应该自动成为普通表单字段；键必须声明归属、配置来源、生效方式和是否需要重启。

## 唯一编辑入口

| 配置 | 唯一入口 | 保存位置 | 生效方式 |
|---|---|---|---|
| 模型、供应商、API 地址、模型密钥、LLM 代理 | 模型与调用 → 模型连接 | 模型 JSON + 本机凭据数据库 | 新调用读取；连接可单独测试 |
| 微信机器人身份 | AI 助手 → 聊天配置；系统页仅保留全局备用名 | 聊天记录 + 本机数据库 | 自动识别优先；全局备用名建议重启后使用 |
| 飞书、邮件、GitHub、Codex 代理保护 | 系统 → 外部服务 | 本机数据库 | 按服务读取方式生效 |
| 数据库地址、Web 端口 | `.env` 或启动命令 | 进程环境 | 必须重启 |
| 插件业务参数 | 自动化与能力配置 | 插件配置 | 按插件声明生效 |
| 群聊触发、角色、记忆覆盖 | 聊天配置 | 本机数据库 | 当前聊天生效 |

模型连接的“本机共享凭据”采用 `env::NAME` 引用格式。Web 界面可直接保存 `NAME` 的真实值，但 API 永远只返回“已配置/未配置”和来源，不返回密钥。这样 `data/llm_models.json` 可以作为分享配置，而真实值留在被忽略的本机数据库或 `.env`。

## 微信备用名称

群聊中的有效机器人名称按以下顺序确定：

1. 自动读取微信群详情里的“我在本群的昵称”；
2. 该聊天手动填写的备用名称；
3. 系统页的“全局备用 @ 名称”。

因此，全局字段不是微信账号展示名，也不是通常需要日常维护的值。项目能成功自动获取群昵称时，它不会覆盖自动结果。填写或修改它会改变自动识别尚未成功时的 `@名称` 匹配，还会影响少数历史消息和日志中的机器人/用户归类。部分插件在初始化时缓存该值，所以界面标记为“需重启”。

## 启动环境与扩展键

Web 端口、数据库连接等值在应用读取当前数据库之前就已经确定，不能通过修改数据库里的同名行来切换。系统页只展示当前来源和状态，不提供无效输入框。

“高级设置”用于脚本和插件声明的扩展键，以及应用内部状态。只有对应文档明确要求时才应修改；核心功能需要在系统设置字段注册表或插件配置规范中声明归属。
