# GGBot v2.2.2：搜索、图片上下文与监听恢复

这是从 v2.2.0 起的累计维护版本，也包含已经打标但未单独发布为 GitHub Release 的 v2.2.1 微信健康链路升级。重点是让长期运行时的监听恢复更克制，让网页搜索和图片输入走统一、可诊断的模型链路，并收敛重复的记忆实现。

## 更新亮点

### 1. 微信监听恢复不再轻易反复重建

- v2.2.1 已将 `/health` 改为读取缓存快照，由单一连接监控线程负责主动探测微信状态，避免健康检查与 UI 自动化竞争。
- 当前版本进一步要求主会话与监听回调的缺口跨多个 watchdog 周期持续存在，才进入重建流程。
- 巡检会使用发送者、消息类型和内容识别同一条候选消息；迟到回调或对应出站活动可以取消尚未执行的重建。
- 同一条未变化的主会话记录不会被重复升级成新的破坏性重建代次。
- 优先调用监听器原生重建能力；传统删除并重新添加监听前，会先确认微信主窗口确实可控。
- 修正会话时间戳对宿主机时区的解释，避免 UTC 与本地时间混用造成误判。

这些改动针对“调出窗口、最小化全部窗口、再次调出并循环”的异常恢复路径，同时保留真实监听失效时的自动恢复能力。

### 2. 普通聊天内置 DDGS 网页搜索

- 普通对话模型先判断本轮是否需要搜索，再由 GGBot 内置 DDGS 执行检索。
- DDGS 不需要账号、API Key 或独立模型路由。
- 可按需读取少量公开网页正文，并限制协议、端口、重定向、响应体大小和内网地址，降低 SSRF 与异常页面风险。
- 搜索结果会作为本轮临时上下文进入最终回复；本地 Codex 仍使用 Codex 原生搜索，不重复调用 DDGS。

### 3. 图片输入严格绑定当前消息

- 支持视觉的聊天模型直接接收本轮图片，不再经过 Chatbot 独立的 OCR 或 vision 路由。
- 非视觉模型使用 `builtin_chat_logger.image_understanding` 生成的场景、对象和可见文字作为降级内容。
- 引用图片下载路径、消息 ID 和当前请求严格绑定；历史聊天中的其他图片块会被清理，防止“这个是谁”等问题误读旧图片。
- 修复图片理解模型主路由失败后无法正确进入降级模型的问题。

### 4. 人物记忆收敛为唯一链路

- 人物证据账本成为人物事实的唯一写入与投影来源。
- 移除旧人物摘要、旧结构化事实写入和重复的 v3 运行路径，减少同一事实被多套逻辑维护的情况。
- 旧数据库表不会在升级时物理删除，但运行时不再读取或写入；结构迁移在启动时自动完成。
- 记忆后台任务、激活流程、重建工具和管理页面统一使用同一组件命名与状态来源。

### 5. LiteLLM 可在管理页面更新

- 模型管理页面可查看当前运行版本、磁盘安装版本和 PyPI 最新稳定版本。
- 更新始终在 GGBot 当前 Python 环境内执行，并固定安装到明确版本。
- 安装后通过独立进程验证导入和版本；验证失败会尝试自动恢复原版本。
- 更新完成后会明确提示需要重启全部服务，避免磁盘版本与当前进程版本混用。

### 6. 续聊与定时任务可靠性

- 群聊无 `@` 续聊不再只依赖问号或再次提及机器人，而是区分回答、结果反馈、追问、纠正、澄清、补充、旁聊和新话题。
- 群聊中插入无关消息不会自动切断原话题，模型会选择最新且确实承接的消息作为回复目标。
- Weekly 在提交托管任务前原子登记调度，并把跨热重载任务锁保存在机器绑定目录，避免插件重载期间重复提交。
- 流式补救请求与普通请求一致地清理内部路由参数，避免供应商收到 GGBot 私有元数据。

## 升级说明

1. 升级前在“系统 → 备份与迁移”中创建并校验一次备份。
2. 本版本新增 `ddgs`、`beautifulsoup4` 和 `packaging` 依赖，请重新执行安装器或运行 `pip install -r requirements.txt`。
3. 更新完成后完整重启 GGBot，使微信桥接、Web 服务、插件和新版依赖同时生效。
4. 人物记忆结构会在启动时自动迁移；不要在迁移期间手工修改记忆数据库。
5. 视觉模型仍必须使用实际支持 OpenAI 多模态内容的供应商适配器；仅设置“支持视觉”不能替代供应商能力。
